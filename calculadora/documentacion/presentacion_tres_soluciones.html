Lo común · El HTML

Los botones llevan una etiqueta pegada

<output id="display" class="display">0</output>

<div class="teclado">
  <button data-accion="borrar">C</button>
  <button data-operador="/">/</button>
  <button data-numero="7">7</button>
  <button data-numero="8">8</button>
  ...
  <button data-operador="+">+</button>
  <button data-numero="0">0</button>
  <button data-accion="igual">=</button>
</div>

Fijaos en los atributos que empiezan por data-. Son atributos inventados por nosotros, y HTML los permite precisamente para eso: guardar información extra en una etiqueta.

  • data-numero → los dígitos del 0 al 9.
  • data-operador → +, -, *, /.
  • data-accion → igual o borrar.
son como las etiquetas de los botes de la cocina. El bote es igual por fuera, pero la etiqueta te dice si dentro hay sal o azúcar.

Desde JavaScript los buscamos con querySelectorAll('[data-numero]')[1] y leemos su valor con boton.dataset.numero[2]. Ojo: data-numero en HTML se convierte en dataset.numero en JS.

Abrir el index.html en el navegador y enseñar los atributos con el inspector (F12). Que vean que los botones son todos iguales salvo por esa etiqueta.

Recalcar: las tres soluciones usan EXACTAMENTE este HTML. Lo único que cambia es el app.js.

Lo común · La memoria

¿Qué tiene que recordar una calculadora?

Haced la prueba mental: tecleáis 15, pulsáis +, tecleáis 4 y pulsáis =. ¿Qué tiene que tener apuntado la calculadora para poder decir 19?

Cuatro cosas, ni una más

  1. Lo que hay en pantalla ahora mismo (4).
  2. El número de antes, el que estaba cuando pulsasteis el operador (15).
  3. La operación pendiente (+).
  4. Una bandera: «el próximo dígito empieza un número nuevo, no lo pegues al anterior».
pensad en un camarero apuntando en una libreta. Tiene que anotar el primer plato, qué queréis hacer con él y el segundo plato. Si no apunta, se le olvida todo.

Esa bandera es la que más lío da. Sin ella, al teclear 15, + y 4 veríais 154 en pantalla. Y no, eso no es una suma.

Cada solución llama a estas variables de forma distinta, pero las cuatro están siempre ahí.

Hacerlo en la pizarra: dibujar cuatro cajas vacías y rellenarlas mientras alguien dicta 15 + 4 =.

Si entienden esta diapositiva, entienden el 80 % de la práctica. Merece la pena pararse aquí.

Lo común · Herramientas que vais a ver

Tres piezas de JavaScript que salen en todas

querySelectorAll

Busca en la página todos los elementos que cumplen un selector y te los da en una lista (una NodeList)[1].

const numeros =
  document.querySelectorAll('[data-numero]');

forEach

Recorre esa lista y hace lo mismo con cada elemento, uno detrás de otro[4].

numeros.forEach(boton => {
  // aquí, "boton" es cada uno
});

addEventListener

Le dice a un elemento: «cuando te hagan clic, ejecuta esta función»[5].

boton.addEventListener('click', () => {
  // esto pasa al hacer clic
});
el addEventListener es como poner un timbre en una puerta. Nadie hace nada hasta que alguien lo toca. Y cuando lo toca, suena exactamente lo que vosotros hayáis decidido.

Solución 0

La solución de clase

Agrupamos los botones en tres montones (números, operadores y acciones) y sacamos las cuentas a una función aparte que se llama calcular(). Una función que recibe datos, devuelve un resultado y no toca nada más.

Esta es la que hicimos juntos en clase. Por eso la explico primero: ya os suena.

Solución 0 · Paso 1

La función calcular(): una máquina de zumo

function calcular(numero1, numero2, operacion) {
    let resultado = 0;

    switch (operacion) {
        case '+':
            resultado = numero1 + numero2;
            break;
        case '-':
            resultado = numero1 - numero2;
            break;
        case '*':
            resultado = numero1 * numero2;
            break;
        case '/':
            if (numero2 === 0) {
                resultado = 'Error';
            } else {
                resultado = numero1 / numero2;
            }
            break;
    }

    return resultado;
}
una exprimidora. Le metéis dos naranjas y le decís «zumo». Os devuelve zumo. No le importa de qué frutero vienen las naranjas ni dónde vais a poner el vaso.

Eso es lo que llamamos una función pura: todo lo que necesita le entra por los paréntesis y todo lo que produce sale por el return. No lee la pantalla. No cambia variables de fuera.

El switch mira el valor de operacion y salta al case que coincide[6]. El break es el freno: sin él, seguiría ejecutando los casos de debajo.

¿Y si dividimos entre cero? Devolvemos el texto 'Error'. Hito 7 resuelto… en parte.

abrid la consola (F12) y escribid calcular(7, 8, '+'). Debe salir 15. Podéis probarla sin tocar un solo botón: esa es la gracia de una función pura.

Quitar un break en directo y ejecutar calcular(9, 4, '+'). Al no frenar, sigue al caso '-' y devuelve 5. Que lo vean fallar es más didáctico que contarlo.

Solución 0 · Paso 2

La memoria y los tres montones de botones

// Memoria de la calculadora
let empezarNumero = false;
let operadorPendiente = null;
let numeroAnterior = null;
let numeroActual = null;

// Los tres montones de botones
const numeros    = document.querySelectorAll('[data-numero]');
const operadores = document.querySelectorAll('[data-operador]');
const acciones   = document.querySelectorAll('[data-accion]');
const pantalla   = document.querySelector('output');

null significa «aquí todavía no hay nada». No es cero: es vacío a propósito.

Los botones se separan en tres grupos según su etiqueta data-. Así, cada grupo tiene su propia forma de reaccionar.

es como ordenar la ropa sucia en tres cestos: blanca, color y delicada. Cada cesto va a su programa de lavadora.

10 números + 4 operadores + 2 acciones = 16 botones, 16 escuchadores.

Pregunta al grupo: «¿por qué empezarNumero empieza en false y no en true?». Respuesta: al arrancar hay un 0 en pantalla, y el primer dígito ya lo sustituye por la comprobación de pantalla === '0'.

Solución 0 · Paso 3 · Hito 1

Cuando pulsáis un número

numeros.forEach(numero => {
    numero.addEventListener('click', () => {
        const valor = numero.dataset.numero;

        if (pantalla.textContent === '0' || empezarNumero) {
            pantalla.textContent = valor;   // sustituye
            empezarNumero = false;
        } else {
            pantalla.textContent += valor;  // pega detrás
        }
    });
});

Solo hay dos posibilidades, y el if las separa:

  1. Sustituir lo que hay. Pasa si en pantalla hay un '0' (así evitamos el feo 07) o si venimos de pulsar un operador.
  2. Pegar detrás. En cualquier otro caso: teclear 1 y luego 2 da 12.

El || se lee «o». Basta con que se cumpla una de las dos condiciones.

textContent siempre es texto. Por eso '1' + '2' da '12' y no 3. Aquí nos viene de maravilla.

Teclear 0, 0, 7 en la calculadora real: se ve 7, no 007. Luego comentar la línea de la comprobación del '0' y repetir.

Solución 0 · Paso 4 · Hitos 2 y 5

Cuando pulsáis un operador

operadores.forEach(operador => {
    operador.addEventListener('click', () => {
        const valor = operador.dataset.operador;

        if (operadorPendiente !== null && empezarNumero !== true) {
            // Ya había una cuenta a medias: subtotal
            numeroActual = Number(pantalla.textContent);
            numeroAnterior = calcular(numeroAnterior, numeroActual, operadorPendiente);
            pantalla.textContent = numeroAnterior;
        } else {
            // Primera vez: solo guardamos
            numeroAnterior = Number(pantalla.textContent);
        }

        operadorPendiente = (numeroAnterior === 'Error') ? null : valor;
        empezarNumero = true;
    });
});

Aquí está el truco de las operaciones encadenadas. Al pulsar un operador nos preguntamos: ¿ya había una cuenta a medias?

  • No → guardamos lo de la pantalla en numeroAnterior y punto.
  • Sí → calculamos el subtotal ya, lo enseñamos y lo guardamos como nuevo «número de antes».

Number() convierte el texto de la pantalla en un número de verdad[7]. Sin eso, calcular sumaría textos.

Y al final levantamos la bandera empezarNumero = true: el próximo dígito empieza número nuevo.

La condición empezarNumero !== true evita un fallo curioso: si pulsáis + dos veces seguidas, no se calcula nada raro, solo se cambia el operador.

La línea del ternario: si la cuenta dio Error, anulamos el operador para no seguir operando con un texto.

Solución 0 · Paso 5 · Hitos 3 y 6

El igual y el borrar comparten montón

acciones.forEach(accion => {
    accion.addEventListener('click', () => {
        const valor = accion.dataset.accion;

        switch (valor) {
            case 'igual':
                if (operadorPendiente !== null) {
                    numeroActual = Number(pantalla.textContent);
                    numeroAnterior = calcular(numeroAnterior, numeroActual, operadorPendiente);
                    pantalla.textContent = numeroAnterior;
                }
                operadorPendiente = null;
                empezarNumero = true;
                break;

            case 'borrar':
                pantalla.textContent = '0';
                operadorPendiente = null;
                empezarNumero = true;
                break;
        }
    });
});

Los dos botones de acción viven en el mismo grupo, así que un switch decide qué hace cada uno.

Igual: si hay una cuenta pendiente, la resuelve con calcular(), la pinta y cierra la operación (operadorPendiente = null).

Borrar: pone la pantalla a '0' y olvida la operación.

fijaos en que el bloque del igual repite casi letra por letra el subtotal del operador. Cuando veáis código repetido, pensad: «esto podría ser una función». Esa idea la recoge la Solución 1.

Pregunta: ¿qué pasa si pulso = sin haber pulsado ningún operador? Respuesta: el if no entra y no pasa nada. Bien pensado.

Solución 1

Un escuchador por botón

Cada botón sigue teniendo su propio addEventListener, pero ya no piensa: solo pasa el recado a una función con nombre propio. agregarNumero, seleccionarOperador, calcular y borrar.

La idea que quiero que se lleven: separar QUIÉN avisa (el botón) de QUÉ se hace (la función).

Solución 1 · La idea

El botón avisa, la función trabaja

en un restaurante, el camarero no cocina. Toma nota y se la pasa a la cocina. Si mañana cambiáis la receta, no tenéis que reeducar a los camareros: solo al cocinero.

En la Solución 0, el código de «qué hacer» estaba dentro de cada escuchador. Aquí lo sacamos fuera, a funciones con un nombre que se entiende al leerlo.

Y aparece una función nueva muy humilde: actualizarDisplay(). Es la única que toca la pantalla.

// 1. Selección del DOM: 5 selectores
const display = document.getElementById('display');
const botonesNumeros    = document.querySelectorAll('[data-numero]');
const botonesOperadores = document.querySelectorAll('[data-operador]');
const botonIgual  = document.querySelector('[data-accion="igual"]');
const botonBorrar = document.querySelector('[data-accion="borrar"]');

// 2. Memoria
let operandoActual = '0';
let operandoAnterior = null;
let operacion = null;
let reiniciarDisplay = false;

// 3. La única puerta a la pantalla
function actualizarDisplay() {
    display.textContent = operandoActual;
}
operandoActual es texto ('0', con comillas). Lo guardamos así a propósito para poder pegar dígitos: '1' + '2' → '12'. Solo lo convertiremos en número en el momento de calcular.

Ahora el igual y el borrar tienen su propio selector con querySelector (en singular), porque solo hay uno de cada.

Solución 1 · Hitos 1 y 2

agregarNumero y seleccionarOperador

function agregarNumero(numero) {
    if (reiniciarDisplay) {
        operandoActual = numero;
        reiniciarDisplay = false;
    } else {
        operandoActual = (operandoActual === '0')
            ? numero
            : operandoActual + numero;
    }
    actualizarDisplay();
}

function seleccionarOperador(nuevoOperador) {
    if (operacion !== null && !reiniciarDisplay) {
        calcular();          // subtotal (hito 5)
    }
    operandoAnterior = operandoActual;
    operacion = nuevoOperador;
    reiniciarDisplay = true;
}

La lógica es la misma que en la Solución 0, pero ahora trabajamos sobre la variable y al final llamamos a actualizarDisplay().

Esa línea con ? y : es el operador ternario[8]. Es un if/else de bolsillo:

condición ? siEsVerdad : siEsMentira

Leedlo así: «¿hay un 0? Entonces pon el número; si no, pégalo detrás».

En seleccionarOperador, si ya había una cuenta a medias, llamamos a calcular() antes de apuntar la nueva operación. Mismo truco del subtotal, sin copiar código.

Si a alguien el ternario le cuesta, que lo reescriba como if/else. Funciona igual. El ternario es comodidad, no magia.

Solución 1 · Hitos 3, 4 y 7

calcular(): ahora sin parámetros

function calcular() {
    if (operacion === null || operandoAnterior === null) return;

    const anterior = parseFloat(operandoAnterior);
    const actual   = parseFloat(operandoActual);
    let resultado;

    switch (operacion) {
        case '+': resultado = anterior + actual; break;
        case '-': resultado = anterior - actual; break;
        case '*': resultado = anterior * actual; break;
        case '/': resultado = (actual === 0) ? 'Error' : anterior / actual; break;
        default: return;
    }

    if (typeof resultado === 'number') {
        resultado = Math.round(resultado * 100000000) / 100000000;
    }

    operandoActual = resultado.toString();
    operacion = null;
    operandoAnterior = null;
    reiniciarDisplay = true;
    actualizarDisplay();
}

Primera línea, el portero: si no hay nada que calcular, return y fuera. Se llama «cláusula de guarda» y os ahorra un if gigante.

parseFloat() convierte el texto en número[9]. Hace lo mismo que Number() en nuestro caso.

El redondeo multiplica por cien millones, redondea al entero con Math.round[10] y vuelve a dividir. Resultado: como mucho 8 decimales. Los números de JavaScript tienen precisión limitada[7], y por eso 10 / 3 sin redondear da ese …35 final tan raro.

esta calcular() no es pura: lee y modifica las variables de fuera. Es cómoda, pero ya no podéis probarla sola en la consola como en la Solución 0.

Hacer en la consola: 10 / 3 y luego Math.round(10 / 3 * 100000000) / 100000000. Que vean la diferencia.

typeof resultado === 'number' evita intentar redondear el texto 'Error'.

Solución 1 · Hito 6 y los escuchadores

borrar() y quién avisa a quién

function borrar() {
    operandoActual = '0';
    operandoAnterior = null;
    operacion = null;
    reiniciarDisplay = false;
    actualizarDisplay();
}

botonesNumeros.forEach((boton) => {

botonesOperadores.forEach((boton) => {
    boton.addEventListener('click', () => {

botonIgual.addEventListener('click', () => calcular());
botonBorrar.addEventListener('click', () => borrar());

borrar() deja las cuatro variables exactamente como estaban al cargar la página. «Estado de fábrica».

Mirad ahora los escuchadores. Cada uno tiene una sola línea dentro: llamar a la función que toca con el dato del botón.

Si mañana queréis que la calculadora funcione también con el teclado del ordenador, ya tenéis las funciones hechas. Solo tendríais que llamarlas desde otro sitio.

Cuenta de escuchadores: 10 + 4 + 1 + 1 = 16. Los mismos que en la Solución 0.

Reto opcional para los rápidos: añadir un escuchador de 'keydown' en document que llame a agregarNumero cuando se pulse una tecla del 0 al 9.

Solución 2

Delegación de eventos

Las funciones son idénticas a las de la Solución 1. Lo que cambia es cómo nos enteramos de los clics: en lugar de 16 escuchadores, ponemos uno solo en el contenedor .teclado.

Aviso al grupo: esta es la forma que más vais a ver en código profesional. Merece la pena entenderla bien.

Solución 2 · El concepto

El clic sube como una burbuja

Cuando hacéis clic en un botón, el navegador no avisa solo al botón. Avisa al botón, luego a su padre, luego al padre de su padre… hasta llegar arriba del todo. Eso se llama burbujeo (event bubbling)[11].

el conserje de un edificio. En lugar de poner un timbre distinto en cada piso con su propio vigilante, todos los paquetes llegan a la portería. El conserje mira la etiqueta del paquete y lo sube al piso que toca.

Así que, si ponemos el escuchador en .teclado, se entera de todos los clics de sus botones. Uno para gobernarlos a todos.

<button data-numero="7"> ← aquí hacéis clic
⬆ sube
<div class="teclado"> ← aquí escuchamos
⬆ sube
<main class="calculadora">
⬆ sube
<body>

Dibujar las cajas una dentro de otra en la pizarra (como muñecas rusas) y una flecha que sale del botón hacia fuera.

Solución 2 · El código

Un único escuchador hace de conserje

const display = document.getElementById('display');
const teclado = document.querySelector('.teclado');

teclado.addEventListener('click', (evento) => {
    // 1. ¿Qué botón se ha pulsado?
    const boton = evento.target.closest('button');
    if (!boton) return;

    // 2. Leemos su etiqueta
    const numero   = boton.dataset.numero;
    const operador = boton.dataset.operador;
    const accion   = boton.dataset.accion;

    // 3. Repartimos el trabajo
    if (numero !== undefined) {
        agregarNumero(numero);
    } else if (operador !== undefined) {
        seleccionarOperador(operador);
    } else if (accion === 'igual') {
        calcular();
    } else if (accion === 'borrar') {
        borrar();
    }
});

Paso 1. evento.target es el elemento exacto donde cayó el clic[12]. closest('button') busca, desde ahí hacia arriba, el botón más cercano[13]. Si el clic cayó en el hueco entre dos botones, no hay botón: null → return.

Paso 2. Leemos las tres etiquetas posibles. Un botón solo tiene una; las otras dos valdrán undefined[2].

Paso 3. Según cuál tenga valor, llamamos a la función que toca. El conserje sube el paquete al piso correcto.

Lo de closest: hoy los botones solo tienen texto, pero si mañana le metéis un icono <span> dentro, event.target sería el span. closest os salva de ese susto.

Solución 2 · Dos detalles finos

¿Por qué !== undefined y no un simple if (numero)?

Si un botón no tiene data-numero, boton.dataset.numero vale undefined. Por eso preguntamos exactamente eso.

«Ya, Ramón, pero if (numero) es más corto». Cierto. Y en este caso funcionaría, porque '0' como texto cuenta como verdadero (es truthy)[14].

pero si algún día ese valor fuera el número 0 o un texto vacío '', el if lo trataría como falso y la tecla dejaría de funcionar. Comparar con undefined dice exactamente lo que queréis decir. Sin sustos.

Botones nuevos, cero cambios

Con 16 escuchadores, un botón que se añade después de cargar la página no tiene escuchador: no funciona hasta que le pongáis uno.

Con delegación, el escuchador está en el padre. Cualquier botón nuevo con su data-numero funciona al momento. Lo acabáis de ver en la demo.

Escuchadores: 1. Selectores: 1 (más el display).

en la consola del navegador: Boolean('0') → true; Boolean(0) → false. Ahí suele estar el lío.

Si sobra tiempo, abrir version-2 y, desde la consola, crear un botón con document.createElement y appendChild en .teclado. Funciona sin más.

¿Cómo se entera cada una de que pulsáis un número?

Solución 0

numeros.forEach(numero => {
  numero.addEventListener('click', () => {
    const valor = numero.dataset.numero;
    // ...toda la lógica aquí dentro
  });

El escuchador piensa y trabaja.

Solución 1

botonesNumeros.forEach(boton => {
  boton.addEventListener('click', () => {
    agregarNumero(boton.dataset.numero);
  });
});

El escuchador solo pasa el recado.

Solución 2

teclado.addEventListener('click', e => {
  const boton = e.target.closest('button');
  if (!boton) return;
  if (boton.dataset.numero !== undefined)
    agregarNumero(boton.dataset.numero);
});

Un solo escuchador para todos.

Fijaos en la evolución: de «cada botón lo hace todo», a «cada botón avisa», a «un único conserje para todo el teclado».

Esta diapositiva es la que mejor resume la sesión. Si solo pudieran quedarse con una, que sea esta.

Comparativa · Mi recomendación

¿Cuál uso?

Solución 0

Para aprender. Todo está a la vista dentro de cada escuchador y la función calcular() pura se prueba sola.

Solución 1

Para ordenar. Cuando el código empieza a crecer, las funciones con nombre os salvan la vida.

Solución 2

Para trabajar de verdad. Muchos elementos iguales o creados sobre la marcha: un escuchador en el padre.

🧩 Retos para casa

  1. Arreglad el NaN que aparece al operar después de un Error.
  2. Añadid el redondeo a la Solución 0 sin romper su función pura.
  3. Llevad a la Solución 2 la idea de la 0: que calcular(anterior, actual, operacion) reciba los datos y devuelva el resultado.
  4. Añadid una tecla . para decimales. Pista: no dejéis que se escriban dos puntos.

El reto 3 es el más interesante: mezcla lo mejor de la 0 (función pura) con lo mejor de la 2 (un escuchador). Es, en el fondo, la «solución 3».
