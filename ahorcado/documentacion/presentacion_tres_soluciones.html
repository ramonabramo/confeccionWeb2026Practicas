Lo común · Herramientas que vais a ver

Cuatro piezas de JavaScript que salen en las tres

Elegir al azar

const i = Math.floor(Math.random() * lista.length);

Math.random() da un decimal entre 0 y 1, sin llegar a 1[4]. Multiplicado por la longitud y redondeado hacia abajo con Math.floor()[5], da una posición válida.

¿Está dentro?

'PANTALLA'.includes('A');  // true

includes() funciona con textos[6] y con arrays[7].

El bucle que destapa

for (let i = 0; i < palabra.length; i++) {
  if (palabra[i] === letra) tablero[i] = letra;
}

Recorre la palabra entera, así destapa todas las apariciones y no solo la primera.

Escuchar al jugador

boton.addEventListener('click', jugar);

«Cuando pase esto, llama a esta función»[8]. Lo que cambia entre soluciones es dónde se pone.

Probar en la consola Math.random() varias veces y luego Math.floor(Math.random() * 8). Que vean que nunca sale 8.

Solución 1 · Hito 1

Sacar una palabra y taparla

function iniciarJuego() {
  const indice = Math.floor(Math.random() * PALABRAS.length);
  palabraSecreta = PALABRAS[indice];

  letrasAdivinadas = [];
  for (let i = 0; i < palabraSecreta.length; i++) {
    letrasAdivinadas.push('_');
  }

  letrasUsadas = [];
  fallos = 0;
  juegoTerminado = false;
  // ... esconder piezas, activar la caja y pintar
}

Tres bloques, tres ideas: sortear, tapar y poner el marcador a cero.

El tablero se pinta con letrasAdivinadas.join(' ')[9], que convierte ['_', '_', '_'] en el texto _ _ _.

sacáis una papeleta de la bolsa y dibujáis en la pizarra tantas rayitas como letras tiene.

iniciarJuego() se usa al cargar y cada vez que se pulsa «Nueva Palabra». Por eso pone todo a cero: la segunda partida no puede heredar nada de la primera.

Preguntar qué pasaría si no se pusiera fallos = 0 aquí. Respuesta: la segunda partida empezaría con los fallos de la primera.

Solución 1 · Hito 2

El portero de la discoteca

function procesarLetra() {
  if (juegoTerminado) return;

  const letra = inputLetra.value.trim().toUpperCase();
  inputLetra.value = '';

  if (!/^[A-ZÑ]$/.test(letra)) {
    mostrarMensaje('Introduce una letra válida (A-Z).', 'aviso');
    return;
  }
  if (letrasUsadas.includes(letra)) {
    mostrarMensaje(`La letra "${letra}" ya está probada.`, 'aviso');
    return;
  }
  letrasUsadas.push(letra);
  // ... acierto o fallo
}

Antes de jugar la letra, se limpia: trim() quita espacios[10] y toUpperCase() la pasa a mayúscula[11], porque las palabras del banco están en mayúsculas.

Después, dos filtros. La expresión /^[A-ZÑ]$/ con test()[12] solo deja pasar una letra de la A a la Z o la Ñ. Y includes descarta las repetidas.

un portero que mira primero el DNI y luego la lista de invitados. Si falla cualquiera de las dos cosas, return, a la calle, y el juego se queda como estaba.

El return temprano es la idea importante de esta diapositiva. Sin él, una letra repetida contaría como fallo.

Si preguntan por la expresión regular: ^ es «empieza», $ es «termina», y entre medias un solo carácter de la lista.

Solución 1 · Hitos 3 y 4

¿Está o no está?

if (palabraSecreta.includes(letra)) {
  for (let i = 0; i < palabraSecreta.length; i++) {
    if (palabraSecreta[i] === letra) {
      letrasAdivinadas[i] = letra;
    }

  mostrarMensaje(`¡Acierto! ...`, 'exito');
} else {
  fallos++;
  dibujarSiguienteParte(fallos);

actualizarPantalla();
verificarFinJuego();

Un if / else y nada más. Si está, el bucle recorre la palabra entera y destapa cada posición que coincide. Si no está, se suma un fallo y se enciende una pieza.

Las dos últimas líneas se ejecutan siempre: repintar la pantalla y preguntar al árbitro si el partido ha terminado.

un break dentro del bucle, o usar indexOf, destapa solo la primera A de PANTALLA. Es el fallo más típico de este hito.

Pedir a alguien que lea el código en voz alta como si fuera castellano. Es la gracia de la versión 1: se lee como la regla.

Solución 1 · Balance

Lo bueno y lo mejorable

👍 Lo que hace bien

  • Se lee de arriba abajo, como la regla del juego.

Solución 2 · Los datos

Palabras con ficha y un Set para las usadas

const BANCO_PALABRAS = [
  { palabra: 'CSS', categoria: 'Diseño Web',
    pista: 'Hojas de estilo en cascada...' },
  // ...
];

let partidaActual = null;
let letrasAdivinadas = [];      // ['', 'S', 'S']

Cada palabra viaja con su categoría y su pista. Al sortear, se guarda la ficha entera en partidaActual y se usa partidaActual.palabra, partidaActual.pista…

Las letras probadas van en un Set[2]: una colección que no admite repetidos. Se trabaja con add, has y clear.

Y el tablero se rellena con Array(n).fill('')[14]: huecos vacíos en vez de guiones, porque cada letra se pinta en su propia casilla.

por eso la victoria se comprueba con !letrasAdivinadas.includes(''), no con '_'. Quien copia de la Solución 1 gana nada más empezar.

Comparar new Set() con un array en la consola: s.add('A'); s.add('A'); s.size da 1.

Solución 2 · El teclado

27 botones que no están en el HTML

function renderizarTecladoVirtual() {
  tecladoVirtual.innerHTML = '';
  LETRAS_ALFABETO.forEach(letra => {
    const btn = document.createElement('button');
    btn.type = 'button';
    btn.className = 'tecla';
    btn.textContent = letra;
    btn.dataset.letra = letra;
    tecladoVirtual.appendChild(btn);
  });
}

En el index.html el teclado es un div vacío. Los botones los crea JavaScript con createElement[15] y los mete dentro con appendChild[16].

Cada botón lleva su letra apuntada en dataset.letra[17], que en el HTML aparece como data-letra="A".

la etiqueta con el nombre en la taquilla del gimnasio. Lo de dentro da igual: la etiqueta dice de quién es.

¿La ventaja? Si mañana queréis añadir la Ç, se cambia una cadena de texto, no el HTML.

Inspeccionar el teclado con F12 para que vean los data-letra generados. Recalcar que no están en el index.html original.

Solución 2 · Delegación de eventos

Un solo conserje para 27 teclas

tecladoVirtual.addEventListener('click', evento => {

Cuando hacéis clic en una tecla, el evento no se queda en ella: sube por sus padres. Es el burbujeo[18]. Así que basta un escuchador en el contenedor.

evento.target[19] dice dónde se hizo clic; closest('.tecla')[20] sube hasta la tecla, o da null si se pulsó en un hueco.

Solución 2 · Teclado físico

Dos puertas, un mismo pasillo

window.addEventListener('keydown', evento => {
  if (evento.ctrlKey || evento.altKey || evento.metaKey) return;
  const letra = evento.key.toUpperCase();
  if (LETRAS_ALFABETO.includes(letra)) {
    jugarLetra(letra);
  }
});

El evento keydown[21] en window se entera de cualquier tecla pulsada en la página. evento.key[22] trae el carácter.

Lo bonito es la última línea: llama a la misma jugarLetra() que el ratón. Toda la lógica está en un solo sitio; las entradas son solo puertas.

sin la primera línea, Ctrl+R para recargar contaría como haber pulsado la R.

Remarcar el principio: separar «cómo me llega la letra» de «qué hago con la letra». Es la semilla de la Solución 3.

Solución 2 · Balance

Lo bueno y lo mejorable

👍 Lo que hace bien

  • Mucho más cómoda de jugar: ratón, dedo o teclado.
  • Un solo escuchador para 27 teclas, aunque se regeneren en cada partida.
  • Toda la lógica de una jugada en una función: jugarLetra().

👎 Lo mejorable

  • jugarLetra() decide las reglas y pinta la pantalla. Mezcla dos trabajos.
  • Siguen siendo variables globales.
  • Al recargar, se pierde todo: no hay historial de partidas.

Preguntar: si quisiéramos hacer una versión del juego para consola, sin HTML, ¿qué parte de jugarLetra podríamos aprovechar? Casi nada, porque está mezclada con el DOM. Esa es la puerta a la Solución 3.

Cuatro clases, cuatro trabajos

La columna de la derecha es la clave. Si una clase hace algo de esa columna, el reparto está mal hecho.

Solución 3 · El motor

El árbitro devuelve un informe, no pinta nada

probarLetra(letra) {
  if (this.juegoTerminado || this.letrasUsadas.has(letra)) return null;

  this.letrasUsadas.add(letra);
  const acierto = this.itemActual.palabra.includes(letra);

  if (acierto) { /* rellenar this.letrasAdivinadas */ }
  else { this.fallos++; }

  const max = this.configDificultades[this.dificultad].maxFallos;
  const victoria = !this.letrasAdivinadas.includes('');
  const derrota = this.fallos >= max;
  if (victoria || derrota) this.juegoTerminado = true;

  return { letra, acierto, fallos: this.fallos, maxFallos: max,
           victoria, derrota, palabraSecreta: this.itemActual.palabra };
}

Las reglas son las de siempre, pero todo lo «del objeto» lleva this. delante[25]: this.fallos, this.letrasUsadas…

Y en vez de pintar, devuelve un objeto con el resultado de la jugada. Quien lo llame decidirá qué hacer con él.

Las vidas dependen de la dificultad: 8 en fácil, 6 en normal, 5 en difícil. Y en difícil hay además un reloj de 45 segundos: la interfaz lo descuenta con setInterval[26] y, al llegar a cero, el motor da la partida por perdida con tiempoAgotado().

el motor funciona sin pantalla. En la consola: const m = new AhorcadoEngine(); m.iniciarNuevaPartida(); m.probarLetra('A');

Hacer la prueba de la consola en directo. Es la mejor demostración de que el motor está desacoplado: juega sin HTML.

Solución 3 · La interfaz

El marcador lee el informe y pinta

jugar(letra) {
  const res = this.engine.probarLetra(letra);
  if (!res) return;

  const tecla = this.dom.teclado.querySelector(`[data-letra="${letra}"]`);
  tecla.disabled = true;
  tecla.classList.add(res.acierto ? 'acierto' : 'fallo');

  if (res.acierto) {
    this.audio.playSuccess();
    this.renderPalabra();
  } else {
    this.audio.playError();
    this.dom.partesSvg[res.fallos - 1].classList.add('visible');
    this.actualizarSalud();
  }
  if (res.victoria || res.derrota) this.finPartida(res);
}

Fijaos en lo que no hay: ni un includes, ni un bucle sobre la palabra. La interfaz pregunta al motor y obedece.

Los escuchadores se escriben con funciones flecha[27]:

this.dom.teclado.addEventListener('click', evento => {
  const tecla = evento.target.closest('.tecla');
  if (tecla) this.jugar(tecla.dataset.letra);
});
con function (evento) {...}, dentro del escuchador this sería el teclado, no la interfaz, y this.jugar no existiría.

Este es el error número uno de la Solución 3. Mostrarlo en directo: cambiar la flecha por function y enseñar el error en la consola.

Solución 3 · Los ayudantes

Memoria entre visitas y sonido sin archivos

📒 StatsRepository

save() {
  localStorage.setItem(this.STORAGE_KEY,
    JSON.stringify(this.stats));
}

localStorage solo guarda texto[24]. Por eso el objeto de estadísticas se convierte con JSON.stringify al guardar y con JSON.parse al leer[28].

una libreta que el navegador deja en un cajón. Cerráis la página y la libreta sigue ahí.

🔊 SoundSynthesizer

const osc = this.audioCtx.createOscillator();
osc.frequency.setValueAtTime(587.33, ...);
osc.start();

La Web Audio API[23] fabrica el sonido con un oscilador: una frecuencia, una forma de onda y una duración. No hay ni un MP3 en la carpeta.

Y el botón de silencio también se recuerda en localStorage.

Abrir F12, pestaña Aplicación, Almacenamiento local, y enseñar la clave ahorcado_stats_pro_2026 con su JSON.

Solución 3 · Balance

Lo bueno y lo mejorable

👍 Lo que hace bien

  • Cada clase se entiende y se prueba por separado.
  • El motor podría usarse en otro diseño de pantalla sin tocar una línea.
  • Estadísticas que sobreviven a la recarga y niveles de dificultad.

👎 Lo mejorable

  • Mucho más código para el mismo juego: hay que conocer clases, this y flechas.
  • Para un ejercicio pequeño puede ser matar moscas a cañonazos.
  • Más piezas, más sitios donde equivocarse con un nombre.

Mensaje final del bloque: la 3 no es «la buena» y las otras «las malas». Es la que escala mejor cuando el proyecto crece.

Comparativa · El mismo momento, tres códigos

¿Cómo se entera cada una de que habéis jugado una letra?

Solución 1

btnProbar.addEventListener(
  'click', procesarLetra);
inputLetra.addEventListener(
  'keydown', e => {
    if (e.key === 'Enter')
      procesarLetra();
  });

La letra se lee de la caja dentro de procesarLetra().

Solución 2

tecladoVirtual.addEventListener(
  'click', e => {
    const t = e.target
      .closest('.tecla');
    if (t) jugarLetra(
      t.dataset.letra);
  });

La letra llega como parámetro, venga del ratón o del teclado.

Solución 3

this.dom.teclado
  .addEventListener(
  'click', e => {
    const t = e.target
      .closest('.tecla');
    if (t) this.jugar(
      t.dataset.letra);
  });

Igual que la 2, pero llama a un método y este pregunta al motor.

Que señalen las diferencias entre la 2 y la 3. Solo son this. y que jugar() no decide nada.

Respuestas: 1) palabra, tablero, letras probadas, fallos y si ha terminado. 2) los arrays empiezan en 0. 3) el escuchador está en el contenedor y el clic sube por burbujeo. 4) un objeto con el resultado; porque las reglas no deben depender de la pantalla. 5) localStorage solo guarda texto.
